# 2026.326.0938 — test(bed): the box bed exercises the install-content builder rule

## Summary

`charly box validate` now asks the build's own question (opencharly/sdk#608).

- `validateBuilders` calls `deploykit.NeedsBuilder`, the SAME rule the render and the apply compile use, so validate and build cannot disagree about whether a candy needs a builder. The box `BuildFormats` set and `candyHasFormatConfig` are deleted with it.
- `candyHasInstallFiles` takes the project's builder vocabulary, so a candy whose only content is a builder manifest (`mise.toml`) is install content exactly when a builder in that vocabulary detects it — and still refused when none does.

The repo's R10 bed exercises this: `check-box-local` gains `box-builder-manifest-install-content`, which runs `charly box validate` on a scratch project both ways — a candy whose only content is a `mise.toml` must validate clean (the arm that depends on the rule reading the builder vocabulary), and a candy with no install content must still be refused. `check-live` reports `12 steps: 12 passed, 0 failed, 0 skipped`, and the arm list is pasted below.

`TestValidatePkgConfigReadsManagerDeclarations` pins the manager loop: a candy whose arch tag carries an `aur` manager with a `module:` requirement and no packages is reported against `distro.arch.aur` — a label only that loop can produce — and the same declaration with packages is not reported.

**Also in this change.**

- `validate_rules.go`: `validatePkgConfig` now iterates `m.TagSections[*].Managers` instead of `m.FormatSections`, so a manager declaration's diagnostic is identified as `distro.<tag>.<manager>.module` rather than `<format>.module` — the same move the contract makes elsewhere (a manager is a tag declaration, not a format).
- `validate_rules.go`: `candyHasFormatPackages` is deleted and `candyHasAnyPackages` is reshaped to `candyHasTagPackages ∪ TopPackages`, with `candyHasTagPackages` absorbing manager-level packages — so a candy whose only packages are a manager declaration still counts as having packages.
- `validate.go`: a `vctx.builders()` accessor (nil-safe) is the one place the install-content rule reads the project's builder vocabulary.
