# 2026.293.1153 — feat(validate): fail on a missing skill body, composition-independent

## Summary

`charly box validate` now fails when an authored `skill:` node has no body at the path the loader reads.

`CollectSkills` gates body reads on `BoxCandyChain` — a label-size policy, documented in its own comment as
*"union-of-composed-only, which bounds the label size"*. Whether a body **exists** is not a label question, so that gate
must not decide it. A repo that authors `skill:` nodes but composes no box had no call site that ever read a body, which
is why `charly box validate` returned `0 warnings, 0 errors` on a tree whose body sat at a path nothing reads.

Filed as `opencharly/opencharly#530`. Producer half merged in `opencharly/sdk#430`; this is the consumer.

```go
// candy/plugin-box/validate_skills.go — extracted so the behaviour is testable without a resolved
// project envelope; called from runValidateEngine after runRawConfigChecks.
func validateSkillBodies(cfg *spec.Config, dk map[string]deploykit.CandyModel, e *vErr) {
	if cfg == nil {
		return
	}
	if _, err := deploykit.CollectSkillBodies(cfg, dk); err != nil {
		e.Add("skills: %v", err)
	}
}
```

`cfg` is the `loadRawProjectConfig(ctx, exec, dir)` result already loaded in `runValidateEngine`; `vc.dk` is the
`map[string]deploykit.CandyModel` that `newVctx` already builds. No new plumbing.
