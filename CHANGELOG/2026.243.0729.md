# 2026.243.0729 — feat(validate): say what was checked, so a passing gate can be evidence

## Summary

`charly box validate` printed **nothing** on success. `emitVerdict` returned `nil` with no
output, so a PR body could only assert "it passed" and a reviewer asking for pasted output had
nothing to read.

That produced real friction: a reviewer blocked a PR for *"How tested lacks pasted output"*;
the author pasted `$ charly box validate` / `exit 0`; the reviewer correctly called that a
reconstruction rather than a transcript. The only way to produce evidence was to measure the
command's silence:

```
$ charly box validate > /tmp/v.txt 2>&1; echo "exit=$?"; wc -c < /tmp/v.txt
exit=0
0
```

Measuring a byte count to prove emptiness is a workaround for a gate that should speak for
itself. Every other gate here names what it proved — `task verify` reports
`349 submodules, policy B holds`; a check bed reports `PASS (steps=12)`. Success now does too:

```
charly box validate: OK — checked 489 candies, 38 boxes, 29 deploys, 7 distros, 7 builders; 3 warnings, 0 errors
```

Zero-valued collections are omitted, so a single-candy repo reads
`OK — checked 1 candy; 0 warnings, 0 errors` rather than padding the line.

### The warning count is real, and was nearly not

A first draft printed `0 warnings` on a run that had just emitted two, because scan advisories
were stderr writes in `sdk/loaderkit` and never reached diagnostics. That is worse than
printing nothing — it reads as a cleared gate. I removed the claim rather than ship it wrong,
then fixed the cause instead of deferring it:

| Repo | Role |
|---|---|
| opencharly/spec#85 | the `ScanSeams.Warn` seam |
| opencharly/sdk#200 | the arbiter routes through it (required sink, no shim) |
| opencharly/plugin-build#7 | the validate path collects advisories as diagnostics |
| **this PR** | the count is reported |

Warnings are counted from the SAME merged diagnostics the error verdict filters, so the number
cannot drift from what the reader sees above the line.

**Merge ordering:** this PR is last in that chain and its `3 warnings` output depends on the
three above it.

## How tested

```
$ go build ./... && go vet ./... && go test ./...
ok  	github.com/opencharly/plugin-box/candy/plugin-box	0.006s
```

**Live**, with charly built against all four repos in the chain via `replace`:

```
$ charly box validate
charly box validate: OK — checked 489 candies, 38 boxes, 29 deploys, 7 distros, 7 builders; 3 warnings, 0 errors
```

Three warnings — two version-skew, one shadow note. Verified the binary actually carried the
change by first building **without** it and confirming no summary line appeared.

**Negative controls — each guard reproduces the failure it prevents.**

Deleting `fmt.Println(summary.String())`:

```
--- FAIL: TestValidateSummaryIsActuallyPrintedOnSuccess
    validate_summary_test.go:91: stdout
```

Deleting the warning tally:

```
--- FAIL: TestValidateSummaryCountsWarningsFromTheSameDiagnostics
    Warnings = 0, want 2 (errors must not be counted as warnings)
```

The first control matters most. My initial suite asserted the string's *shape* but never that
it reached stdout — deleting the `Println` left every guard green. That is exactly the "test
that cannot fail" R7 rejects, so the suite now captures `os.Stdout` and proves the line is
emitted on success and **absent on failure**, so a failing gate can never be quoted as passing.
