# refactor(cli)!: delete the dead `box pull --platform` flag, its help text and its test

## Summary

`charly box pull --platform <os/arch>` did not select anything. `pullGrammar.Platform` was parsed by
Kong and **never read** — `dispatchPull` invokes the compiled-in `build:ensure` word over the
`InvokeProvider` reverse leg and threads no platform into the ensure drive — so the flag and its help
string advertised a capability that does not exist, and the doc corpus taught users to type it.

**Deleted rather than implemented**, by operator mandate ("remove any outdated or orphaned code or
functionality as part of the ledger") and by design: platform selection is being implemented where it
is real — a plugin artifact's descriptor selection (`sdk/artifactkit`'s `SelectArtifact`, which works
because an artifact KNOWS its platforms) and the registry consumption legs. For an IMAGE pull, if it
is ever needed, the home is the engine/drive interface, never a charly flag. A second spelling on
`box pull` would only mislead.

**Four surfaces deleted, one cutover (R5):**

1. `pullGrammar.Platform` — the field, with its help text (`candy/plugin-box/box.go`).
2. The comment asserting the flag's no-op behaviour — *"--platform stays a no-op (the former Run
   never threaded it to the ensure drive either)"* — a comment asserting a mechanism that is gone is
   the same defect as the flag.
3. `TestPullGrammar_Parse`'s `--platform` argument and `g.Platform` assertion.
4. `TestPullGrammar_Parse_MinimalArgs`'s `g.Platform` assertion.

The test now asserts the **opposite** — that `box pull --platform` fails to parse — so a re-added
spelling with no consumer behind it fails loudly instead of being silently accepted a second time.
