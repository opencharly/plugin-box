# 2026.320.0100 — feat(inspect): decode the candy views before printing them

## Summary

The **last** consumer leg of the IR opacity, on `opencharly/sdk` `v0.2026320.32`. Closes **opencharly/plugin-box#83**.

Three commands read the candy views directly, and those views now carry bytes (`spec#336`):

| command | site | change |
|---|---|---|
| `charly box list volumes` | `inspect_list.go:366` | decodes `CandyView.Volumes` before printing |
| `charly box list aliases` | `inspect_list.go:378` | decodes `CandyView.Aliases` |
| `charly box inspect --format aliases` | `inspect_list.go:228` | decodes `ResolvedBoxView.Aliases` |

**One asymmetry worth naming, because the code reads two forms side by side:** `#ResolvedBoxView.volumes` was **not** converted — it is `[...#ResolvedVolumeMount]` and stays a slice (spec#336 converted only its `aliases`). So `box inspect` decodes aliases while reading volumes directly. Each site carries a comment saying which form it is, so the next reader does not have to re-derive it.

**No new mechanism.** Every decode is `sdk/rawbody.Decode`, the one crossing `sdk#538` consolidated.

- **`listVolumes` / `listAliases`** — `inspect_list_opaque_test.go` (NEW) builds both `CandyView` bodies with the producer's encoder and asserts the printed rows, so a revert to reading the slice prints **nothing** and fails. It also pins the empty case: a view with no volumes/aliases prints nothing rather than a zero row.
- **`inspect --format aliases`** — the existing `inspect_list_test.go` fixtures build the `ResolvedBoxView.Aliases` body through `rawbody.Encode`.

That fixture work also surfaced the asymmetry above: `ResolvedVolumeMount` is still a slice, and an early attempt of mine to encode it failed the build.
