# 2026.272.2039 — fix(plugin-box): adopt the sdk ctx requirement on the deploy-config family

## Summary

`sdk#288` (`v0.2026271.915`) added a **`context.Context` parameter** to the `deploykit`
deploy-config family, removing the fail-open default so each invocation resolves its OWN
per-box overlay via `kit.DefaultDeployConfigPath(ctx)`. Without a bumped `sdk`, this plugin's
compiled-in candy cannot build against the `#717` fix version (`sdk v0.2026272.1813`), which
blocks `opencharly/charly#733` → `#714`. This PR adopts `ctx` in `plugin-box` and bumps
`sdk`/`spec` to the ctx-ready tags.

### Threaded the REAL ctx (no fabrication — it removes one)

`plugin-box` is a compiled-in `command:box` plugin whose provider dispatches via
`Invoke(ctx, req)`. That genuine ctx is held in the `hostClient{ctx, exec}` built at the
Invoke entry and is already consumed by the sibling handlers (`dispatchGenerate`,
`dispatchFeature`, `dispatchInspect`, …). `dispatchLoad` was the ONE handler that took only
`args` and **fabricated `ctx := context.Background()` locally** — the exact anti-pattern
`sdk#288` removed. It now receives the `hostClient` and uses `hc.ctx` for BOTH the
`ResolveContainer` call and the `TransferImageToVenue` exec, so resolution and transfer
address the same invocation ctx.

### Call sites changed

| File | Change |
|---|---|
| `box.go` | `dispatchBoxCommand`: `dispatchLoad(args)` → `dispatchLoad(hc, args)` |
| `box_load.go` | `dispatchLoad(args)` → `dispatchLoad(hc *hostClient, args)` |
| `box_load.go` | `deploykit.ResolveContainer(g.Target, g.Instance)` → `(hc.ctx, …)` |
| `box_load.go` | `ctx := context.Background()` → `ctx := hc.ctx` |
| `box_load.go` | dropped the now-unused `context` import (R5) |
