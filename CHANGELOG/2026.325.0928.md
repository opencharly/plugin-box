# 2026.325.0928 — feat(validate)!: the content kinds own their nodes' rules; an owned skill node is install content

## Summary

The validate engine's half of opencharly/sdk#598.

1. **The content kinds own their nodes' rules.** `validate_skills.go` is DELETED. Its rules (an image owner, sdk#434; a body that does not exist at the owner's repo root, opencharly/opencharly#530) belong to `kind:skill` (opencharly/plugin-harness-kind, D-PLUG-1), which also installs and labels the skills, so the gate and the build read one rule. The engine now asks every content kind (the host's `content_kinds`) in **project scope** through `InvokeProvider` `ops.OpContent`, and reports each diagnostic as `kind "<word>": <diagnostic>`. A kind that cannot be asked is itself a finding, never a silent pass.
2. **An owned skill node is install content.** `validateCandyContents` accepts a candy whose only content is the `skill:` nodes it owns (the build installs their bodies), so a skill carrier needs no install step of its own.

The `check-box-local` bed gains `box-skill-owner-is-install-content`, and its `box-skill-image-owner` step passes unchanged against the moved rules (its comment updated). The validate skill's install-source list names owned skill nodes.
