# 2026.305.2226 — feat(box): `box load --kind <cluster>` delivers into a k8s node's containerd through the verified venue seam

## Summary

`charly box load` can deliver an image into a pod's **nested podman store**; it cannot deliver
one into a **Kubernetes node's containerd**. That is the gap this adds: a `--kind <cluster>`
target that streams the image into the named kind cluster's control-plane node through the same
venue seam the rest of the deploy machinery uses, instead of a hand-run `podman save | ctr import`
spike.

| Path | What it changes |
|---|---|
| `candy/plugin-box/box_load.go` | `charly box load --kind <cluster>`: `dispatchLoad` learns a `kind` arm that resolves the cluster's control-plane node as the venue, then drives `loadIntoKindNode` → `deploykit.NewNodeVenue` → `TransferImageToVenue`. The verification is the seam's (the load is probed and re-streamed once rather than trusted on an exit code). |
| `candy/plugin-box/box_load_kind_test.go` | Unit coverage for the argument/venue resolution (no cluster needed). |
| `candy/plugin-box/box_load_kind_live_test.go` | **The live gate**: drives the REAL changed path against a REAL kind cluster and asserts the node's containerd ends up holding the image, probed through `ctr`. It **skips visibly** (never fakes) unless `CHARLY_KIND_BOXLOAD_CLUSTER` names a running cluster. |

The branch also carries a sync merge with `main` (`c2d7102`), so it is current — no content of
its own.

### Review round 1 — both code findings fixed in-tree

1. **R1 (a false comment).** `loadIntoKindNode` claimed the `-n k8s.io` scope is "reused verbatim
   by the probe, the tag, the removal and the load — the ONE place the store scope is decided",
   while `kindCtrImportArgv` re-specified the namespace for the load. Both halves were false; the
   comment now states what the code does.
2. **R2 (a duplicated constant).** The store scope was decided twice. It is now ONE constant,
   `kindCtrNamespace` — the venue's store-kind verb builds `ctr -n <ns>` from it and
   `kindCtrImportArgv` derives its own `-n` from the same constant, so the load cannot drift into
   a namespace kubelet never reads while the probe stays green. The unit test still pins the
   resulting argv.

Both fixes are code, so the live gate was re-run on the fixed tree (below) rather than assumed to
still hold.
