# 2026.327.0328 — fix(validate): a remote candy the rule cannot read is an error, never a silent pass

## Summary

opencharly/plugin-box#95 measured `charly box validate` answering **`0 warnings, 0 errors`** for a project whose imported namespace carried a document the *same binary* refuses. The finding is now `R1`-closed in two parts:

- **The two paths agree on the current head** (measured below, cold and warm cache): the imported candy manifest is read and refused, naming its file — so the specific divergence no longer reproduces. Nothing regressed: a rule that READS a document refuses it.
- **The mechanism that could silently restore it is fixed.** `validateCandyCUESchemas` decided each candy's verdict inline and `continue`d whenever it could not open the manifest — including a REMOTE candy whose namespace failed to materialize. A rule that cannot see a document reported nothing, which is exactly how the filed measurement read `0 errors` about a refused document. The per-candy decision is now `candyManifestVerdict`: an inline/synthesized candy (no manifest of its own, body gated at load) stays skipped, and the REMOTE arms are errors naming the candy and the path they expected.
