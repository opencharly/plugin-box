# 2026.301.1944 — test(skills): the skill-body control reads the tree, so no body is left unchecked

Closes #67

## Summary

Head `350f885c923742f89e9f40afdd703879ca92b160` — the commit this PR pushes: **2 files changed, 167 insertions(+), 3 deletions(-)**.

**The defect.** The control that keeps this repo's skill bodies true — `candy/plugin-box/skill_doc_flags_test.go` — compared the bodies it reads against a hand-kept list of ten names (`skillDocCases`). That list was the control's only source of the SET of bodies: it read exactly the ten bodies it named, and asserted only what those bodies claim. A body added under `.agents/skills/` was therefore read by NOTHING, and the control stayed green over it.

That is not a hypothetical gap. Every `.agents/skills/<verb>/SKILL.md` in this repo is published VERBATIM into the opencharly/marketplace corpus, and every harness loads that corpus. The class of defect this control exists to catch is a body that documents a flag the grammar does not define — the class that produced `--platform` (opencharly/plugin-box#40) and the inner-concurrency flag (#65), each of which published a command that fails AT THE FLAG. A body the control never reads is a body that can carry that class into the corpus with nothing to see it.

**The RCA.**

- **Mechanism** — `skillDocCases` was a hand-kept list of the ten body names, and the control iterated it. The corpus generator, in contrast, reads the TREE. Two sets: the published one (the tree) and the checked one (the list). The control never compared them, so the difference was invisible from the inside: the list is only ever wrong in the one direction no assertion could see.
- **Missed control** — nothing bound the control's read-set to the tree. Every other assertion in the control is about the CONTENT of a body it reads; there was no assertion about WHICH bodies it reads.
- **Blast radius** — the whole published corpus of this repo's verb skills. A body that documents a flag the grammar does not define could reach the corpus, and the control that exists to catch exactly that would not see it.
- **Root fix** — the TREE names the bodies. The control derives the set from `.agents/skills/` (`skillBodyNames`) and asserts BOTH directions: every body in the tree has a case, and every case names a body that exists. It also asserts that every body it reads makes at least one usage claim, so a case cannot pass by comparing nothing.

**A second defect, found while proving the new arm.** The bed's step wrote its evidence with `>>` and never truncated the log, so an assertion could be satisfied by a PREVIOUS run's output. MEASURED: the new arm, mutated so the body sits at the repo root — which makes the arm's expectation false — still PASSED, against the log the green run had left behind. Both logs are now truncated at the start of the step, so every assertion in the step reads THIS run.

**What lands.** Two files:

| file | what it carries |
|---|---|
| `candy/plugin-box/skill_doc_flags_test.go` | the coverage control: the tree names the bodies, both directions are asserted, and no body may be read vacuously |
| `charly.yml` | the bed's skill-owner step: a new arm that pins the skill-body lookup's base, plus the truncation of the step's two logs |

**The lookup's base, pinned.** The bed's skill-owner step proves that a skill's prose is readable when the owner is a package candy; its control puts the body at that candy's REPO ROOT. MEASURED, and now held by an arm: the body lookup reads the owning candy's repo root, and the SAME body BESIDE the candy is REFUSED — *"no .agents/skills/psk1/SKILL.md exists at the repo root of the owning candy"*. The arm holds that base, so the fixture's placement cannot drift back to a claim the lookup does not make.
