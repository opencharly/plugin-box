# 2026.281.0737 — feat(box): closure-aware reconcile — compute the target over the whole closure, report what it cannot repair (charly#737)

## Summary

`charly box reconcile` aligned pins **per project**: `reconcileCandidateFiles` walks only
`<dir>/charly.yml` + `box/` + `candy/`, so the per-repo target was computed over *this project's own*
references alone. A repo this project happens to pin **once** therefore read *"already reconciled"*
while the closure it actually composes needed a newer tag — and the next partial repin made the skew
**worse** (`distro-cachyos#123` advanced one manifest and left the old ref behind in another, one day
before the audit that filed this issue).

Fixes opencharly/charly#737's closure half.

### Measured live, on the charly tree itself, with this plugin compiled in

```
### PER-PROJECT (default):
would rewrite 18 pin(s):
### CLOSURE:
692 pin(s) in OTHER repos of this project's closure disagree with the closure-wide target —
this project cannot rewrite them, the owning repo must:
  github.com/opencharly/layer-k3s (candy/charly-marketplace/charly.yml): v2026.272.0223 -> v2026.277.1356
  github.com/opencharly/plugin-kube (charly.yml): v2026.272.0236 -> v2026.276.1350
  github.com/opencharly/distro-fedora (charly.yml): v2026.256.1134 -> v2026.274.2213
```

**The per-project answer was 18; the tree's real disagreement count is 692.** That gap *is* the
defect.

### Why a closure-wide *write* is impossible, and what the fix does instead

The other repos in the closure are **read-only shared cache exports**; a single project cannot
rewrite their pins without corrupting the pristine cache. So `--closure` does the only correct thing
one project can:

1. **COMPUTE** the target over the **whole closure** — this project's own manifests **plus every
   pinned `@github` repo's own manifests, transitively**, walked read-only out of the fetch cache;
2. **REWRITE** only this project's **own** files to that closure-wide target; and
3. **REPORT** the skew it cannot repair — every foreign pin that disagrees, with its `repo@tag` and
   the manifest that carries it.

A ref the walk cannot fetch is **reported, never silently skipped**: a half-known closure must not
read as a fully-reconciled one. That third leg is the honest exit — the tool now states what it could
not fix instead of asserting a property it never checked.

what voided `#24`'s coverage silently.
