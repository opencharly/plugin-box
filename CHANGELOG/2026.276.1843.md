# 2026.276.1843 — fix(box): split the plugin-capability diagnostic's two faults (pb#24)

## Summary

`charly box validate` reported **one** Go-side diagnostic for **two** different faults:

```
candy %q: plugin capability %q is malformed (want <class>:<word>)
```

For a **well-formed** `<class>:<word>` pair whose class the pinned `spec` does not declare, that
message is false - the grammar IS correct; the class is simply not in the pinned vocabulary. The
CUE bound check rejects the same value with the accurate *out of bound* message, so the Go
diagnostic contradicted the schema that owns the value. Filed as #24 with the reproduction path:
at the plugin-lobster root `charly box validate` fails this way while the spec leg that adds the
`workflow` provider class is unlanded, and the message sends the reader to fix a word that is
already right.

**Fix** - `candy/plugin-box/validate_rules.go`:

- `splitPluginCapability` now returns a **three-valued fault** - `capFaultNone` /
  `capFaultMalformed` / `capFaultUnknownClass` - instead of a single `ok bool`, so the caller can
  word each fault truthfully.
- The unknown-class arm emits
  `plugin capability %q: unknown provider class %q (known: <sorted spec.ProviderClasses>)` -
  naming the class AND the set it was checked against.
- `is malformed (want <class>:<word>)` is kept for the grammar arm, where it is true.
- The known-class list is rendered once, **sorted** (`knownProviderClasses`): `spec.ProviderClasses`
  is NOT in sorted order (it follows the CUE declaration order), and the message must not reorder
  with a spec bump.

**No rule, marker or acceptance changed**: the same values are still rejected, at the same severity.
Only one finding's wording changed, plus the fault enum that selects it. **No new gate** - the CUE
bound check already rejects the value (visible in the section 3 output below); this fixes the
companion diagnostic that contradicted it.

Diff - 5 files: the two Go files under `candy/plugin-box/`, the root `charly.yml` (which
gains the two bed entities - a **config** change, and the one that gives this repo a witness),
a new `.gitignore` entry for the generated `.check/` run state, and a documentation-accuracy
fix in `AGENTS.md`:
