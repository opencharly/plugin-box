# 2026.302.0039 — fix(skills): the skill body's base is the owning candy's repo root, in the pin, the assertions and the prose

Refs opencharly/plugin-box#73

## Summary

Head `b860c11b51e71f64b402d7f7704069722c9ad0f5` — 5 files changed, 125 insertions(+), 58 deletions(-).

**This repo's own unit tests asserted a skill-body base that the org's build does not use.** The base was unified onto the owning candy's **REPO ROOT** (`sdk/deploykit/candy_repo_root.go` → `candyRepoRoot`), and the sdk the org's build compiles resolves the body there. This repo's own `go.mod` still floored the sdk at a version from **before** that unification, and under THAT floor the body resolved at the owning candy's **own directory** instead.

The two bases disagree for every candy under `candy/<name>/` — which is every real skill owner in this org — so the repo's own `go test ./...` was green over behavior the shipped binary does not have, and the repo's prose named the dead base:

- `candy/plugin-box/validate_skills.go` said the body resolves at `<owning candy SourceDir>/.agents/skills/<name>/SKILL.md` — the OLD base.
- `charly.yml`'s `check-box-local` bed said the lookup *"did NOT look beside the candy"* — the ORG's answer, in a past tense that reads as the opposite of what it means, and in a file pointer (`skills_collect.go`) that no longer holds the base.

The `charly/pr-validator` review of opencharly/plugin-box#66 raised it as *"One documentation nuance (not a functional defect)"*. It is a documentation nuance only because the prose picked ONE of the two answers without saying which build it held for — and the repo's own tests picked the other one.

**What this change does:**

| file | what it does |
|---|---|
| `candy/plugin-box/go.mod` | the sdk floor is advanced to `v0.2026297.1851` — the version the org's build compiles — so this repo's own build resolves bodies the way the shipped one does |
| `candy/plugin-box/go.sum` | the checksums the new floor carries (74 insertions, 34 deletions) |
| `candy/plugin-box/validate_skills.go` | the doc comment names the **REPO ROOT** base, and says why the two bases diverge |
| `candy/plugin-box/validate_skills_test.go` | the three assertions that encoded the OLD base are flipped to the ONE base, and the file's header says why they are a floor guard |
| `charly.yml` | the bed's prose is corrected: the past-tense negative becomes the present tense, the file pointer becomes `candy_repo_root.go`, and the sibling comment's stale pointer is fixed |

**The two prose statements and the three assertions now name ONE base, and the repo's own build proves it.** A Go module pin is a FLOOR, not a ceiling: the org's build compiles this plugin against the HIGHEST sdk in the graph, so `charly`'s own pin silently raised the floor above this repo's and moved the behavior under this repo's feet. Advancing the floor here closes that gap — and makes the flipped assertions a **standing guard**: lowering the pin again turns them RED.
