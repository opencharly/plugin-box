## RCA — the duplication

The same question ("what is a repo's newest tag?") was answered by two paths with different
caching/transport:

| path | function | transport | caching |
|---|---|---|---|
| `reconcile --remote` → `reconcileTargetVersion` | `refs.GitLatestTag` | raw `git ls-remote --tags` | **none** (per call) |
| bare `@github` ref resolution | `gitClient().LatestTag` | cached | 1h TTL, disk-persisted, cross-process |

`refs_collect.go` documents why the cached one exists: the raw per-process `ls-remote` fanout was
measured at **90–94 concurrent `ls-remote` → GitHub throttling**. So the raw path was a known-bad
pattern the other path already fixed, yet `reconcile --remote` still used it — and the two could
disagree inside one run.

## Change

`reconcileTargetVersion` now resolves through the cached **`latestTagFn`** (a package var over
`gitClient().LatestTag`, the `sync.Once` singleton over `refs.NewGitClient("")`), not the raw
`refs.GitLatestTag`. One newest-tag path. (Import grouping matches the package convention.)
