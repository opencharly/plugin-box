# 2026.296.1100 — docs(build): the build skill documents the charly image store, not the retired tag step (#62)

## Summary

Corrects the `build` skill's "Build Flow Details" paragraph, which still described the retired
`LoadExport`: load → tag → verify bridge and claimed a dependent box's `FROM ${BASE_IMAGE}` resolves
through the local registry.

It now documents what W3.6 (opencharly/plugin-build#37) implements:

* every export is NAMED — `io.containerd.image.name=<FullTag>` plus
  `org.opencontainers.image.created` — and written to the **charly image store**, one engine-neutral
  OCI layout at `$XDG_DATA_HOME/charly/images` (`CHARLY_IMAGE_STORE_DIR` for a disposable target);
* a locally present parent is solved **from the store** as an `--oci-layout` named context, with the
  registry as the fallback;
* the engine materialisation is a plain `load` with **no tag step** — the annotation names the image
  and the drive verifies the reference resolves.

One file: `.agents/skills/build/SKILL.md` (+5/−1). Prose only; no code, pin, or config changed.
