# 2026.301.1542 — refactor(cli)!: the build concurrency flag is --stage-parallelism, and a control holds every skill body to the grammar

## Summary

Head `cdc2a9577f2a86ef698dc6400eb0d4c17d2886a9` — the commit this PR pushes: **5 files changed,
345 insertions(+), 27 deletions(-)**.

**The inner-concurrency flag of `charly box build` is renamed to the contract's spelling —
`--stage-parallelism` / `CHARLY_STAGE_PARALLELISM`. `--podman-jobs` / `CHARLY_PODMAN_JOBS` are
removed: no alias, no shim, no deprecation window.** This is a breaking change to the CLI
surface, which is why the title carries the `!` marker.

The BuildKit cutover (opencharly/opencharly#481) renamed the knob `podman_jobs` →
`stage_parallelism` in the CONTRACT — the schema key (`spec/schema/box.cue:120-121`), the sdk
symbol (`sdk/buildkit.ResolveStageParallelism`), the config key in every `defaults:` block, and
the prose (opencharly/layer-charly-build#29, merged 2026-10-19, validator PASS). The Kong
grammar in THIS repo was the one surface that did not follow it, and it was false about its own
mechanism: the flag's help read *"Stages per podman build"* for a driver that is deleted — the
value drives the BuildKit daemon's `[worker.oci] max-parallelism`
(`sdk/buildkit/build_helpers.go:44-47`).

That left two live defects, and this PR fixes both:

1. **The published build skill documented a spelling the grammar rejected.**
   `.agents/skills/build/SKILL.md` is published VERBATIM into the opencharly/marketplace corpus,
   so every harness that loads the corpus was handed a command that fails AT THE FLAG:
   `charly box build --stage-parallelism N` → `charly: error: command "build": unknown flag
   --stage-parallelism` (rc=80, measured against the shipping binary — the live proof is pasted
   under **How tested**).
2. **The pull skill documented `--platform`,** a flag deleted from the pull grammar by #40 while
   the body kept its alias-table row and its flag bullet.

Both are the same class, so both get the same control:
**`candy/plugin-box/skill_doc_flags_test.go` reads each of this repo's ten skill bodies from the
path the corpus reads it from, and asserts that every flag and every environment binding each
body presents for its OWN command is one that command's Kong grammar actually defines.** The flag
names and env bindings come from Kong's own parser model, so the surface cannot drift; it is a Go
test and not a prose review because a prose review cannot fail (R7). It reads three claim
surfaces — usage claims (a fenced line or inline span that invokes the command), alias rows (a
table row whose first cell is a `--flag`), and flag-section bullets — and it deliberately does NOT
read prose that merely mentions the command, because that prose names the HOST's surface (`-C`,
`--dir`, `CHARLY_PROJECT_DIR`), not this plugin's. Both exclusions are stated RULES about which
SURFACE is read, not an allowlist of names, so a later prose rewrite cannot smuggle a false flag
in through a sentence.
