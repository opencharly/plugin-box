# 2026.331.0902 — feat(plugin-box)!: follow the spec module's Android removal

## Summary

The spec module's Android retirement (spec `v0.2026331.808`) removed the `CandyModel.Apk` field and the `ApkPackageSpec` type. This repo's `candy/plugin-box` validate engine still referenced both, so the module did not compile against the new contract:

```
$ cd candy/plugin-box && go build ./...
./validate_rules.go:202:28: m.Apk undefined (type spec.CandyModel has no field or method Apk)
./validate_rules.go:262:53: undefined: spec.ApkPackageSpec
./validate_rules.go:889:30: m.Apk undefined (type spec.CandyModel has no field or method Apk)
```

This change deletes the Android APK surface the plugin owned:

- `validateCandyApk` — the `apk:` ⊕ `source:` cross-field rule for Android apkeep installs;
- its call site in `validateCandyContents`;
- the `len(m.Apk) > 0` term in `candyHasInstallFiles`;
- `TestValidateCandyApk`, which covered only that removed rule.

Generic kinds (pod / vm / local / kubernetes) and every other package/manifest/task install mechanism are unchanged. The Alpine `apk` package format is a distro-packages surface (`spec.DistroPackages`) and is untouched; the term deleted here was the Android top-level `apk:` candy field.

Dependencies pinned to the merged prerequisites: spec `v0.2026331.808`, sdk `v0.2026331.837`.

### Spike

The cause is a removed contract identifier, so the candidates are narrow and the spec artifact itself settles them:

- **A — delete the Android surface (winner).** The spec module at `v0.2026331.808` declares no replacement for `CandyModel.Apk` / `ApkPackageSpec`, so there is no generic shape into which the rule could be rewritten. The absence is measured against the module source:

  ```
  $ SPECDIR=$(go list -m -f '{{.Dir}}' github.com/opencharly/spec)
  $ echo "$SPECDIR"
  /home/atrawog/go/pkg/mod/github.com/opencharly/spec@v0.2026331.808

  $ grep -rnE '\bApk|Android|GoogleAccount' "$SPECDIR" --include='*.go'
  (no output; exit 1 = no matches)
  ```

  Deleting both sites makes `go build ./...` and `go test -count=1 ./...` green.
- **B — rewrite against a surviving spec type.** Not a plausible candidate: no candidate type exists (the grep above), so a rewrite would invent a contract the spec does not declare.

The diff implements A.

**Live-execution boundary.** The changed validator path did not execute under a live process: `candy/plugin-box` is compiled into the `charly` binary, and the prebuilt binary used for the `charly box validate` run above comes from the `retire-closure` umbrella worktree, so it bakes the previous plugin-box and cannot exercise this diff. That `box validate` run is a STRUCTURAL check of this repo's candy/plugin entity only — it is not proof of the deleted rule. The real gate for the changed code is the module gate: `go build ./...` proves the removed `CandyModel.Apk` / `ApkPackageSpec` references are gone, and `go test -count=1 ./...` runs the surviving package tests. `TestValidateCandyApk` covered only the removed rule, so the compiler is the assertion that the rule's references are absent.
