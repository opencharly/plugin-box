# 2026.288.1448 — fix(workflow): name the millisecond conversion in the readiness message (R3)

## Summary

The previous fix in this file made the timeout message derive its stated bound from `READINESS_WINDOW_MS`, and then
divided by a bare literal:

```js
core.info(`PR #${pr.number} not merged within ${Number(process.env.READINESS_WINDOW_MS) / 60000}m — ...`);
```

**That is an unnamed magic number in the same touched region**, so the file's inline comment and every body that
claims "no unnamed magic numbers" were false. Raised by the validator on opencharly/plugin-task-zzold-6561#4 against
the artefact this source produced.

It becomes a named constant, so the unit conversion is as named as the bound it converts:

```js
const MS_PER_MINUTE = 60000;   // named: milliseconds in a minute
```

Behaviour is unchanged: the message still reports the window the loop actually used. Division is still integer
division, so the rounding is identical.

Closes #54
