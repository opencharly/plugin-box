# 2026.301.1952 — test(skills): the vacuity guard gets its own red arm

Closes #69

## Summary

Head `b2462e48a18f031bbcdde0f6af32e99f8779ec1d` — the commit this PR pushes: **1 file changed, 39 insertions(+), 1 deletions(-)**.

**The finding.** opencharly/plugin-box#68's validator review raised one non-blocking observation: the skill-body control's VACUITY guard — the assertion that a body makes at least one usage claim for the command it documents — has no demonstration that it can fire. The guard is the assertion that stops a case from passing by comparing nothing, and it was the one assertion in that control with no red arm.

**The RCA.**

- **Mechanism** — the rule was asserted inline in the control, as a `len(claims) == 0` test that called `t.Errorf` on the spot. An inline assertion has no seam a test can address: nothing in the suite could hand the rule a body and observe what it decides. The suite's other red arm (`TestSkillDocCoverageIsEffective`) covers the COVERAGE rule, not this one.
- **Missed control** — no test exercised the vacuity branch, so the control's FAILING path had never run. A guard that has never fired is a guard whose absence is silent.
- **Blast radius** — the published corpus of this repo's verb skills. The control exists because every `.agents/skills/<verb>/SKILL.md` here is published VERBATIM into the opencharly/marketplace corpus, and every harness loads that corpus; a body that documents a flag the grammar does not define publishes a command that fails AT THE FLAG. The vacuity guard is the second half of that subject: a body that IS read, but whose prose never invokes its own command, is compared to nothing — the usage claims are what tie a flag in the prose to the grammar. With the guard inverted, every such body would pass the control silently, and the corpus would carry the defect the control exists to catch.
- **Root fix** — the rule moves into a function, `skillDocIsVacuous`, and `TestSkillDocVacuityIsEffective` gives it two arms: a body that never invokes the command it documents (the guard must fire) and a body that does (the guard must stay silent). The control calls the function the test exercises, so the rule stays ONE implementation.

**Why this is a change of its own, and not a filing.** The org's rule is that a finding raised on a PR is fixed or rebutted on the thread with evidence, never filed away. This observation was raised on opencharly/plugin-box#68, and #68 is already merged, so the fix cannot ride on that PR: it is its own change, under its own issue, opencharly/plugin-box#69, filed and claimed before the branch was cut.

**What lands.** One file:

| file | what it carries |
|---|---|
| `candy/plugin-box/skill_doc_flags_test.go` | the vacuity rule as a named function, and the two-arm test that gives it a red arm |

No verb, no flag, no published prose, and no grammar changes: this is a coverage fix to the control that guards the corpus.
